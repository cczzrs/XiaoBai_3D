# 小白 3D 工作台使用说明

本文中代码格式的路径均相对项目根目录。

## 01 · 3D 模型构建

- 已批准头部 `head-v1`：包含头、双眼和鼻子。
- 已批准身体 `body-v7`：完整身体，左右、前后对称。
- 两个原始 GLB 的 SHA-256 与原审批记录一致，直接沿用原世界坐标装配。
- 手臂、腿脚保留候选槽位，可导入独立 GLB 或 OBJ、单独查看、控制显示、移除候选。
- 正面、右侧、背面、左侧和透视视角；网格、线框、拖动旋转、滚轮缩放。
- 头部八视图中的四个正交视图、身体 TIFF 第 1 帧及辅助侧背视图、最后一个手臂动作参考，使用原配准叠图。自由旋转到不匹配的角度时暂停叠图。
- 默认黑色背景、无定向光。背景与灯光设置在两个模块共用，并随项目保存。

候选导入沿用文件的原始坐标和单位，应在云端建模交付时与现有 H100 坐标一致。导入入口不生成新网格、不自动改变头身基线、不将候选标记为批准。OBJ 不加载外部 MTL；GLB 需内嵌缓冲区与纹理。上限默认 50 MiB、200 万顶点、256 个网格、1000 坐标单位包围盒对角线。已带动画或蒙皮的文件不适用于当前静态部件入口。

## 02 · 形体、骨骼和姿态动作设计

- **v59 镜像双臂**：头身与 v59 双臂组合已获用户批准，记录见 `docs/approvals/v59-assembly-approved.json`。手臂曲面、材质、四类显示线、原始坐标和比例保持不变，右臂仍以 X=0 镜像。资源继续保存在 `assets/design/arms-v59/`，原导入记录中的 pending 字段由新批准记录取代，无需改写原资源。旧草稿保留原有候选或空槽，可点击「使用 v59 对称双臂」加入。
- **腿脚 v2**：外形及与已批准头身臂的衔接已获用户批准，记录见 `docs/approvals/legs-v2-approved.json`。保留 v1 下部脚掌顶点，从实际环 Y≈13.4479797 起以三次 Hermite 曲线连接腿部和身体接触环，接触环沿用身体法线。两腿左右镜像，共 52,484 顶点、104,960 三角形；批准资源保持原字节，只在设计模块中使用独立副本。v1 文件继续保留，旧草稿按原版本恢复。
- 「显示 v59 走线」独立控制环线、直线、前斜线和后斜线；与工具栏的三角面「线框」不同。任一四肢关节转角非零时暂时隐藏这些原始显示线，避免未变形的线叠在蒙皮表面；回到中立后恢复。原显示线文件保持不变。
- **形体**：头部整体比例，身体宽度、高度和厚度。设计变换应用到独立副本，切回构建模块显示批准比例。
- **关节绑定 rig-v1（已批准）**：Root → Body → Neck → Head 加左右肩、肘、腕、掌端、髋、膝、踝、脚尖，共 20 个 Bone 节点。双臂和双腿为 4 个蒙皮网格，每个顶点最多 4 个权重；手臂根部锚定身体，腿根接触环锚定 Root，头身沿用刚性层级。4 个掌端/脚尖节点用于定位，由腕/踝带动，不单独驱动表面。
- **绑定检查**：逐关节调整 XYZ 位置偏移和静态 XYZ 转角，支持左右镜像编辑。「回到中立姿态」清除转角与播放姿态、保留关节偏移；「恢复本版关节位置」恢复本版绑定默认值。根关节、颈关节高度及骨骼显示仍可调。默认位置、范围和权重参数统一在 `APP_CONFIG.design.binding` 中。
- **姿态**：头部左右转向、抬低头、侧倾，身体侧倾。
- **动作设计 v1（已批准）**：原地步行 1.2 秒、小跑 0.8 秒、招手 2 秒、思考鼻伸缩 4 秒，以及坐姿保持；沿用此前批准默认角度，27 个动作数值及招手侧逐项可调。切换过渡默认 0.3 秒，支持播放、暂停、逐帧定位、恢复默认与导出五个 GLB 片段。旧点头、摇摆和呼吸仍保留。
- **五官 → 眼睛**：宽度、高度、双眼间距、上下位置、目光偏移、左右眼独立开合；双眼眨眼、左眼眨动、右眼眨动、环顾。左右以正面画面为准。开合与目光只改变眼睛内部亮区，外侧轮廓保持固定；宽高、间距和位置仍是独立的外形参数。
- **五官 → 表情**：自然、可爱、开心、愤怒、思考、惊讶、困倦，表情强度可调。通过内部亮区的弯曲、倾斜、大小和不对称表达情绪，不新增瞳孔或改变眼睛外轮廓。强度为 0 保留基础眼神；与眨眼、环顾和其他动作叠加。
- **五官 → 鼻子**：宽度、高度、上下位置、鼻尖突出、倾斜；支持轻摆和宽度伸缩。
- 眼睛、鼻子和身体的动作可组合，共用播放速度；时间轴按当前全身动作的周期更新，旧动作维持四秒周期，各有独立动作幅度。五官幅度 0 保持静态；静态参数与动作叠加后的值会限制在配置范围内。
- 「面部特写」放大查看五官；「恢复眼睛默认」「恢复鼻子默认」分别恢复该部件及其动作，恢复眼睛同时恢复自然表情。「恢复自然表情」只清除表情预设，保留眼睛基础参数。「重置姿态」重置身体姿态、眼神与开合、表情预设、鼻子倾斜和全部动作，保留五官形体比例与位置。
- **色彩皮肤**：头部、身体、眼睛、鼻子、手臂、腿脚分别设置颜色、粗糙度与皮肤图片。修改颜色或导入图片自动启用自定义材质；取消启用可暂时对照原材质，恢复按钮清除该部位的自定义设置。尚未导入的四肢可先保存外观，模型导入后应用。

五官变形只作用于设计副本的独立几何，使用原头部前表面采样保持贴合。闭眼只把内部亮区收拢为细弯缝，保留外侧眼环；鼻尖突出保持鼻根贴面。极端参数接近头部轮廓时会向可用表面收拢；独立参数不自动消除五官之间的重叠。默认值与重置可逐顶点恢复原五官。

关节绑定 v1 已获用户批准，记录见 `docs/approvals/rig-v1-approved.json`。动作作为独立设计层，沿用原关节静止位置、权重、逆绑定矩阵和中立几何。头身臂腿、rig-v1 和 actions-v1 文件保持原字节。用户已明确批准本轮全部动作效果，记录见 [动作批准记录](approvals/actions-v1-approved.json)，范围见 [动作说明](actions-v1-review.md)。该记录锁定 24 个基线文件；后续参数调整保存在独立副本。

## 材质、背景和光照

- 皮肤和背景接受静态 PNG、JPEG、WebP，每张最多 8 MiB、单边 4096 像素。先校验格式和尺寸，再实际解码；坏图片不会替换当前内容。图片嵌入项目 JSON，不依赖原磁盘路径。
- 导入皮肤时调色设为白色以显示原图色彩；之后颜色与贴图相乘。粗糙度越小，高光越集中。材质仅应用于设计副本，构建模块保持原批准材质。
- 批准模型没有 UV。设计副本使用原始正面 XY 坐标投影，图片按比例居中裁切；贴图随形体和五官动作变形。侧面会有压缩，背面沿用同一投影；它不是完整的手工 UV 展开。已有 UV 的导入模型沿用原 UV。
- **背景设置**位于右侧：纯色、导入图片、等比铺满（裁切）或完整显示（留白）。透明区域和留白显示所选背景颜色；不拉伸图片。
- **视口光照**按指定 `head-v1/head-review.js` 及配置实现：启用定向柔光后关闭强均匀环境光，使用 9 束柔光主光、半球环境光、补光和轮廓光。方位、高度、主光强度及曝光可调，方向相对当前相机；关闭后恢复均匀光。没有新增地面或投影阴影。

## 保存与导出

- **保存草稿**或 `⌘ S` / `Ctrl S`：保存到当前浏览器的 localStorage；刷新后恢复设计参数和候选。容量不足会提示使用 JSON 导出，不会覆盖原文件。
- **项目 JSON**：保存形体、关节、姿态、动作、表情及强度、材质、背景和光照，并嵌入候选模型及图片；顶层 `binding` 保存四肢关节的 XYZ 偏移与转角，`actions` 保存全部动作参数及招手侧。在「打开项目」中完整恢复，恢复后暂停播放。批准头身固定引用项目内原件，内置双臂和腿脚以明确资源标识引用项目内文件。整份项目最多 256 MiB。
- 当前项目 revision 为 8；新项目默认包含 v59 双臂、腿脚 v2 和中立绑定。旧 revision 1–6 草稿补充中立 `binding`，revision 1–7 补充 `actions` 默认参数后迁移，保留历史参数、资源标识、候选模型和空槽；腿脚 v1 仍加载原 v1 文件。点击「使用腿脚 v2 设计副本」才替换当前腿脚候选。未知内置版本拒绝加载，不回退为新版。旧草稿的开合和目光数值沿用，渲染使用新的眼睛内部变化方式。
- **模型 GLB**：导出当前模块、当前可见部件和当前姿态。完整设计副本保留 4 个 skins、20 个骨骼节点、蒙皮权重和逆绑定矩阵，以及实际材质颜色、粗糙度和内嵌皮肤纹理；不生成动画关键帧。构建模块仍导出静态批准部件。GLB 不包含场景背景或灯光对象，可编辑参数通过项目 JSON 恢复。带蒙皮的 GLB 不适用于静态部件导入入口，应使用「打开项目」恢复绑定草稿。
- **动作 GLB**：在姿态动作页「导出全部动作 GLB」，包含步行、小跑、招手、思考和坐姿五个独立片段，保留批准的 20 骨/4 蒙皮，鼻伸缩导出为形态目标；切换过渡由工作台控制，不烘焙进循环首尾。
- **视口 PNG**：仅导出三维画面，不包含参考叠图、工具栏和检查面板。

v59 显示线仅用于评审，不写入模型 GLB；模型导出保留双臂曲面及镜像变换。其显示开关也不写入项目草稿。

本轮动作交付位于 `assets/design/actions-v1/`：`xiaobai-actions-v1.glb` 为五片段动作模型，`project.json` 恢复可调草稿，`default-parameters.json` 和 `provenance.json` 记录默认值与来源。动作交付已批准并锁定；rig-v1 与 actions-v1 的历史 pending 字段均保留原字节，由各自后续批准记录确定当前状态。新导出的 `motionApproval` 仅描述动作定义及参数：批准默认值为 `approved`，修改数值或招手侧为 `modified-design-copy`；它不批准副本的其它形体、绑定或材质改动。

相机、显示开关、参考选择和叠图透明度是临时评审状态，不写入项目草稿。模型和图片先解析并验证，全部成功后才替换项目；任意候选模型或图片失败会保留原装配与外观。
